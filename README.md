# MapChat

A browser-based map app with real-time chat and live GPS location tracking,
built on **Convex + React (Vite) + react-leaflet**. Users pick a username and
optional group, and immediately see each other on an OpenStreetMap with
real-time chat in the corner.

> See [MAP_CHAT_GUIDE.md](./MAP_CHAT_GUIDE.md) for the full feature overview,
> schema, and deployment notes.

## Features

- 🗺 **Live map** — `react-leaflet` + OpenStreetMap tiles
- 📍 **Geolocation tracking** — automatic sharing via `navigator.geolocation.watchPosition` (default 5-second interval)
- 💬 **Real-time chat** — instantly reflected through Convex's reactive queries
- 👥 **Group filtering** — when a group is set, only users in the same group appear on the map and in chat
- 🎯 **Auto-center on login + manual recenter** — the map jumps to your current location exactly once after login; afterwards use the top-right "my location" button to recenter
- 🧑 **Per-user avatar markers** — person-shaped SVG markers, colored deterministically from each user's ID
- ✅ **Shared validation (Zod)** — the same schema is used by both the React client and Convex functions


## Authentication

There is no real authentication. `UsernameInput` collects a username and an
optional group; the `createUser` mutation creates a user record (or refreshes
its `lastSeen`). The session is kept in memory only — closing the tab logs
the user out.

### Username rules

- **6–10 characters**
- ASCII letters (`A–Z`, `a–z`), digits, or any symbol that is valid in the
  local-part of an email address (RFC 5322 unquoted form):
  `! # $ % & ' * + - / = ? ^ _ \` { | } ~ .`
- Disallowed: spaces, non-ASCII characters, and the email-unsafe symbols
  `@`, `(`, `)`, `,`, `:`, `;`, `<`, `>`, `[`, `\`, `]`, `"`

These rules are defined as a Zod schema in
[convex/validation.ts](./convex/validation.ts) and reused by both the client
([src/components/UsernameInput.tsx](./src/components/UsernameInput.tsx)) and
the `createUser` mutation
([convex/myFunctions.ts](./convex/myFunctions.ts)).

## Geolocation behavior

Highlights from
[src/hooks/useGeolocation.ts](./src/hooks/useGeolocation.ts):

- Subscribes to position changes with `watchPosition` and throttles server
  updates to `intervalSeconds` (default: 5 seconds).
- A heartbeat re-sends the last known coordinates on a timer so the server's
  cleanup cron doesn't drop stationary users from the map.
- Deduplicates `watchPosition` so React 18 StrictMode's double-mount in dev
  doesn't spawn two simultaneous geolocation watchers.
- On geolocation errors the previous coordinates are preserved; only the
  error message is updated.

The map is centered by `InitialCenter` in
[src/components/MapView.tsx](./src/components/MapView.tsx): it moves to the
user's location **exactly once**, the first time a real coordinate becomes
available after login. After that, panning and zooming are completely free.
Use the floating "my location" button (top-right) to recenter manually.

## Database schema

| Table       | Fields                                                              | Purpose         |
| ----------- | ------------------------------------------------------------------- | --------------- |
| `users`     | `username`, `lastSeen`, `createdAt`, `group?`                       | Active users    |
| `locations` | `userId`, `username`, `lat`, `lng`, `timestamp`, `group?`           | Latest position |
| `messages`  | `userId`, `username`, `text`, `timestamp`, `receiverId?`, `group?`  | Chat history    |

Stale `locations` (and any users without a remaining location row) are
removed by the cron in [convex/crons.ts](./convex/crons.ts).

## Production deployment

1. Deploy the Convex backend:

   ```bash
   npx convex deploy
   ```

2. Set the production Convex URL so the frontend bundle knows which Convex
  deployment to call. There are two common approaches:

  - Build-time embedding (recommended when deploying a static site):

    - Pass `VITE_CONVEX_URL` as a build arg so Vite inlines it into the
     production bundle. Example with Fly.io:

     ```bash
     fly deploy --build-arg VITE_CONVEX_URL=https://<your-convex>.convex.cloud -a convexchat
     ```

    - Or add it to `fly.toml` so Fly injects it during the build:

     ```toml
     [build]
      args = { VITE_CONVEX_URL = "https://<your-convex>.convex.cloud" }
     ```

  - Runtime fallback (supported by this repo): if `VITE_CONVEX_URL` is
    not present in the bundle, the client falls back to `window.location.origin`.
    This is convenient for testing non-production setups but embedding the
    Convex URL at build-time is more reliable for production hosting or when
    the frontend is served from a different origin than Convex.

3. Build the frontend and deploy to your host (Vercel, Netlify, nginx, Fly, …):

  ```bash
  npm run build
  ```

4. Upload the `dist/` folder (or let your host pick it up). Note: the
  Geolocation API requires **HTTPS** in production (localhost is exempt).

## Customization ideas

- Change the location update interval: edit the `5` in
  `useGeolocation(userId, 5)`.
- Tweak marker appearance: edit the `palette` / SVG inside
  [src/components/icon/PersonIcon.ts](./src/components/icon/PersonIcon.ts).
- Provide a fixed list of selectable groups, or default the group field.
- Adjust the chat history length via the `limit` argument of `getMessages`.
- Add typing indicators, Wake Lock, or `navigator.sendBeacon` on `pagehide`
  for more robust presence tracking.

## Privacy notes

- There is no authentication, so anyone can join with any (validated)
  username. Add rate limiting and proper auth before running in production.
- Locations are stored in Convex and overwritten by every `updateLocation`
  call.
- `locations` rows that haven't been refreshed for more than ~60 seconds are
  removed by the cleanup cron, along with any users that no longer have a
  location.
